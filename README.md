# 吳・古本取名

取名遊戲，全部用字取自 **8 部古籍**：易經、紫微斗數、山海經、神農本草、
道德經、抱樸子、詩經、楚辭。
姓可自行輸入（預設「吳」），名一至二字。**喜用神只有木、火** —— 木為喜用、火為次用。

這 8 部古籍的性質並不相同，引用時不能一律當成「古本經文」：
易經／詩經／楚辭／道德經／抱樸子是**經文**，可逐字查證；
山海經／本草是**名稱索引**（手上沒有原文，只列篇目與藥名）；
紫微斗數是宋明時期的命理系統，不是唐代古本，它的 `note` 是現代描述。
詳見 `VERIFICATION.md`。

[線上玩](https://alastorid.github.io/wubaobao/)

## 喜用神：木、火

原局木弱，火雖有而不得令。所以：

- **木是喜用，首選**，抽籤權重七成。
- **火是次用，輔助**，抽籤權重三成 —— 火有用，但不狂補。
- 介面只有「木火（七三之序）／木／火」三個選項，**沒有金、水、土**。
- 8 部古籍中只有 5 部是經文層（易經、詩經、楚辭、道德經、抱樸子），
  山海經與神農本草是名稱索引，紫微斗數是現代描述。
- 隨機取名時每個字各自按木七火三抽；兩個字都是木的機率約五成，
  火火只約一成，符合「喜木、不狂補火」。

## 玩法

**六爻成卦。** 卦盤只有六條爻線，點任何地方或滑過去都會擲下一爻
（少陰 ⚋ / 少陽 ⚊），並從當前古本抽一個字收進「所收之字」。
**擲滿六爻必定成卦，必定得一個名字**，卦盤自動歸零重新起卦。

八部古本共用同一副卦盤，只是成卦後顯出的經文與抽字來源不同：

| 古本 | 成卦後顯示 | 取字來源 |
| --- | --- | --- |
| 古本易經 | 六十四卦卦名、卦辭、大象傳 | 卦名、彖傳、象傳、大象傳用字 |
| 古本紫微斗數 | 命宮、十四主星、四化、神曜 | 主星名、宮位名、十二神 |
| 古本山海經 | 山海篇目與所載之物 | 山海草木、靈鳥異獸 |
| 古本神農本草 | 出處、歸經、性味、功用 | 經方本草藥名 |
| 古本道德經 | 依六爻定章，得章名與經文 | 樸、儉、慈、若、赤子、赤 |
| 古本抱樸子 | 依六爻定篇，得篇旨與作者 | 煉、壽、誠、忠 |
| 古本詩經 | 依六爻定篇，得風雅頌名句 | 采、佩、蕙、靜、楚、葛、巧、灼、姝、愛、倩 |
| 古本楚辭 | 依六爻定篇，得離騷九歌名句 | 蘭、茝、芳、杜、薜、荔、椒、曼、懷 |

名字會附上每個字的**筆畫、出處與起名寓意**，例如：

> 吳仁容
> 仁 · 4畫 · 古本易經 坤·象 · 厚德仁愛
> 容 · 10畫 · 古本易經 師·象 · 容民畜眾

## 複製名單

名錄開頭有三顆複製鈕，方便把名單貼給老師或命理師，讓人從中挑出
更有 context 的名字：

| 按鈕 | 內容 |
| --- | --- |
| **只複製名字** | 一行一個名字，最乾淨，直接貼出去問 |
| **複製含出處** | 名字 + 拼音 + 五行 + 逐字筆畫與典據 |
| **複製全部** | 加上序號與完整欄位，給需要完整脈絡的人 |

每一列右邊也有「複製」，只複製那一個名字及其出處。

「複製含出處」長這樣：

```
吳果茹　guǒ rú　木 · 木
　果（8畫・古本易經 蒙·象・果決有擔當） 茹（9畫・古本易經 泰·初九・茹茅同心）
成卦：噬嗑
```

走 `navigator.clipboard`；不可用時退回 `execCommand('copy')`
（iPad Safari 常需要）。兩種都失敗會提示請手動選取，不會靜默無反應。
名單清空後複製列自動隱藏。

## 字庫

**120 個**取名用字，**全部只屬木、火兩行**，零重複。

| | 木 | 火 |
| --- | --- | --- |
| 古本易經 | 31 | 10 |
| 古本紫微斗數 | 3 | 1 |
| 古本山海經 | 2 | 0 |
| 古本神農本草 | 28 | 0 |
| 古本道德經 | 2 | 2 |
| 古本抱樸子 | 2 | 0 |
| 古本詩經 | 15 | 6 |
| 古本楚辭 | 15 | 3 |
| **合計** | **98** | **22** |

每個字附：`c` 繁體字、`p` 拼音、`s` 筆畫、`w` 五行、
`book` 出處古本、`cite` 書中出處、`meaning` 起名寓意。

字庫區塊由 `tools/derive-pool.cjs` 從 `js/classics.js` 的實際經文**反推**產生，
不要手改：先掃經文得到「哪些字真的出現、出現在哪裡」，再與木火分類取交集，
`cite` 一律用掃描結果。手寫的出處無法自我驗證，錯了沒人發現。
`tests/namepool.cjs` 有一條斷言逐一掃描全部經文，任何字的 `cite` 對不上就失敗。

- 出處是**取名用典索引**，標明該字取自哪一部、哪一篇，不代表字只見於該處。
- 五行歸屬各姓名學派別有出入，本庫提供固定分類：
  部首／意象 —— 木、禾、艹、竹、亻、羊 → 木；火、日、心、扌、宀 → 火。
- 筆畫取 Unicode Unihan 的 `kTotalStrokes`。**這不是康熙字典筆畫**：
  姓名學用康熙筆畫，兩者對少數字有出入（例：艹部字 Unihan 計 4 畫）。
  這個數字只用於顯示與抽取權重。
- 起名寓意是給孩子的祝願，並非字典完整釋義。
- **紫微斗數不是古本經文** —— 它是宋明時期成熟的命理系統。
  星名與宮名可用作用典，但 `note` 欄（「光明博愛」「印星忠良」）
  是現代命理描述，不是《紫微斗數全書》的引文。
- **神農本草只列《本草經》的藥名**，不含功效敘述。
  引用「神農本草·白芷」指的是《本草經》的白芷條，不是引用某句經文。
- **抱樸子只有 2 字**：這部書偏金丹方技，可用的木火取名字彙本來就少。
  選抱樸子時若湊不出第二個字，`pickGivenName` 會自動放寬到全庫同一行。

來源：[Unicode Unihan 說明](https://www.unicode.org/reports/tr38/)、
[Unicode Unihan 資料](https://www.unicode.org/Public/UCD/latest/ucd/Unihan.zip)。
Unicode 資料授權見 `UNICODE-LICENSE.txt`。

## 姓

姓可以自己改（介面上方「姓」欄位），預設「吳」。

原因是普通話「吳」與「無」同音同調：`吳德`＝無德、`吳明`＝無名、
`吳容`＝無容、`吳嘉`＝無家、`吳門`＝無門、`吳夫`＝無夫。
加了 `SURNAME_CLASH` 連讀檢查，撞到會**重抽**而不是丟掉名字
（否則會違反「擲滿六爻必成名」的承諾）。

## 禁用字與忌字

兩份不同的表，都要擋，但性質不同：

| | 數量 | 性質 |
| --- | --- | --- |
| `BANNED` | 41 | 使用者已用過、不再出現的名字 |
| `TABOO` | 92 | 取名行業本身的忌諱，與誰用過無關 |

`TABOO` 擋的是字本身屬木火但語義或出處不適合取名的字：
`死`（中孚「生死有命」）、`物`（無妄大象）、`劫`與`空`（紫微地劫、地空）、
`夫`（山海經「丈夫國」）、`疾`（紫微疾厄宮）、`獄`（中孚「議獄緩死」）、
`精`（「精液」）、`夷`（平定蠻族之義）、生肖動物、食材、`荔`（俚語「荔枝」）。
每個字都附理由。線上抽名與舊資料過濾都會擋。

指定排除的 29 字：`丞以品妍妤宇宥宸希彤恩承晨晴樂沁沐泓涵淇淳渝澄熙睿祐語霏霖`，
連帶排除 12 個近形近音字：`佑右辰曦琪祺純瑜愉橙叡晶`。

防護會在三層生效：

1. **建字庫時過濾** —— 禁用字與忌字不會進入字庫。
2. **取名前檢查** —— 就算字庫被改壞，含禁用字或忌字的名字也不會寫進名錄；
   撞到「姓＋名」的壞連讀會**重抽**，不會整個丟掉名字。
3. **舊資料過濾** —— 讀名錄時逐項驗過並剔除，`name` 與 `chars` 都查。

**唯一例外：以／樂／語／宥。** 這四個字只出現在「原典逐字引用」裡：
大象傳的「君子以…」句式（64 卦中 59 卦都有）、需與豫的大象「宴樂」「作樂」、
頤的大象「言語」、解的大象「宥罪」。改字等於竄改經典，所以保留原文。
測試會明確檢查這四個字**只出現在經文區塊**，絕不當成取名字。

## 取名字清單（離線產生）

`names-200.md` 是兩份清單：**三個字**（姓 1 + 名 2）**68 個**、
**兩個字**（姓 1 + 名 1）**81 個**。每個名字附拼音、五行、逐字出處，
以及一段口語自我介紹（會說明自己是三個字還是兩個字）。

**三個字 68 個、兩個字 81 個，都不是 100 個。這是如實數量。**

三個字：清掉取名忌字與動詞末字之後，「名 的兩字出自同一句古本經文」湊不出 100 個好名。
硬湊會得到「芙桂」「梅棠」這種兩個香草名並列的填充物。

兩個字：名只有一個字，每個字都要單獨撐得住一個名字。把 100 個排出來才發現
「吳侯」（爵位）、「吳萬」（數量詞）、「吳菌」（菌菇）、「吳時」（一時）、
「吳道」（道路）都不成立，加上會與姓吳連讀成壞詞的德、明、容。

要湊滿只有三條路，都需要先決定：放寬忌字、放寬「同句」限制、或放寬五行。

「引用不混」分三層，層級在清單裡標示出來：

| 層級 | 意思 | 本次數量 |
| --- | --- | --- |
| A | 名 的兩字出自**同一句**古本經文 | 28 |
| B | 名 的兩字出自**成語／名句**（出處另標，不假托成古本） | 0 |
| C | 名 的兩字出自**同一本書**的不同句 | 40 |

A 層最硬：整句引文可在古本經文中逐字查到。B、C 層的出處分別標示，不假裝同句。

C 層配額刻意設小，因為「同本不同句」只能證明兩字出自同一本書，
不能證明兩字之間有關聯。神農本草完全不進 C 層——它是藥名索引而不是句子，
從藥名清單裡任配兩字彼此沒有語意關係。

```bash
node tools/verify-quotes.cjs   # 驗證 96 條 classic 層引文都在 js/classics.js 裡
node tools/gen-names.cjs       # 產生 names-200.md，並自我檢查後才寫出
node tools/audit-docs.cjs      # 驗證文件裡的數字和程式碼一致
```

`tools/audit-docs.cjs` 會檢查文件宣告的字庫數字、名單數字、篇章數字是否
和實際值相同，以及 `names-200.md` 裡每個名字的自我介紹是否真的宣告了
正確的字數與五行措辭。它已接進 `tests/namepool.cjs`，所以跑資料層測試時
一併檢查——文件與程式碼脫節會讓測試失敗，不必靠人眼看出來。

`tools/gen-names.cjs` 產生前會自我檢查，任一條不符就 `exit 1` 不寫檔：
全部木火、無禁用字、無忌字、無重複、拼音全同者已剔除、
三字名的兩字必須同句或同本、動詞與口號字不得作名字末字。

引文比對的效力邊界見 `VERIFICATION.md`：
能驗「引文有沒有被改寫」，驗不了「`classics.js` 本身對不對」。

## 量測與限制

跑 `SOAK_MS=20000 node tests/soak.cjs` 自行取得當前數字，
`tests/soak.cjs` 的 8 秒實測約為平均 16.67ms／幀、p95 18.5ms、零錯誤，
特效節點 90、音訊聲部 40 都是上限值。

**這些是 Mac 上的瀏覽器與模擬尺寸，不是實體 iPad 的 60fps 保證。**
網站是 DOM/CSS，沒有 WebGL，也沒有每幀碰撞迴圈；尊重減少動態效果設定。
音訊以波形量測（AnalyserNode），沒有在實體硬體上用耳朵聽過。

## 已知未解的事

| 項目 | 狀況 |
| --- | --- |
| 名單數量 | 三個字 68 個、兩個字 81 個，不到 100。要湊滿得放寬忌字、放寬「同句」限制、或放寬五行——三者都動到訂下的前提 |
| 喜用神前提 | 本站從未接收出生資料，也沒有顯示盤面。喜用神是使用者提供的前提，站上只負責依它抽字 |
| 玉部與女部 | 瑾瑤珊琦瓏瑄珩瑛瑩（金）、婷姝婕嫣姣姞婵姍（土）這些傳統女名字都因此排除。要納入得放寬五行 |
| 命理性質 | 五行抽籤（`Math.random() < 0.7`）是西方數學化的近似，不是命理。限定喜用神兩行有道理，但用權重抽字不等於「算八字」 |
| 罕用字 | 字庫已過濾一批生僻字（茝、薜、棻、蕤、蔘、蓀等），但沒有逐一驗證教育部標準字表 |
